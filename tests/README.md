# ppgen tests

This is a simple test mechanism. Each subdirectory here contains a ppgen project.

- a ppgen source file (`NAME-src.txt`)
- an `expected/` subdirectory with pre-built output files:
  - `NAME-utf8.txt`
  - `NAME-utf8.txt.bin`
  - `NAME-utf8.txt.json`
  - `NAME.html`
  - `NAME.html.bin`
  - `NAME.html.json`

GitHub Actions is used to test ppgen against this corpus. Each project is
rebuilt from the source file, giving UTF8 and HTML output and the associated
`.bin` and `.json` files. These generated files are then compared to the
pre-built ones in `expected/`. If there is a difference, the test will fail.

As is typical with GitHub Actions, the tests are run on every commit.

The bits to define how to run tests are in
`.github/workflows/build-tests.yml`.

# Changes to "expected/" over time

As ppgen evolves, code changes will naturally lead to changes in the expected
outputs. The developer is responsible for updating the `expected/` corpus to
the new expected output in that case. Those files may be edited by hand, or
else regenerated by ppgen and then committed.

It's important to use the `-a` flag for these generations, since the timestamp
will necessarily always create a diff, and therefore will cause the test to
always fail. Suppressing the HTML file timestamp comment is therefore needed.

# Future possibilities for testing

Obviously we can add more projects to this corpus. The initial few projects
don't exercise every ppgen feature.

Adding tests against the Python code itself may be desirable, e.g. linting with
`flake8`, static checking with `mypy`, or code auto-formatting with `black`.
